# Задача 2: Поле «Проверка» определяется как кастомное поле вместо капчи

## Описание проблемы

На форуме XenForo поле с хэшированным именем `80272cf8...[ntiym2ex]`
с label «Проверка:» определяется как кастомное поле и запрашивает
ручной ввод вместо обработки через captcha_helper.

### Лог ошибки

```
ТРЕБУЕТСЯ РУЧНОЙ ВВОД
Поле:     80272cf8223d9ab8503aef5c693c8d60[ntiym2ex] — «Проверка:»
Селектор: #ctrl_custom_field_ntiym2ex
Задание:  Введите значение для поля '80272cf8223d9ab8503aef5c693c8d60[ntiym2ex]'
```

### HTML поля

```html
<dl class="ctrlUnit customFieldEditndq5ody limited">
    <dt><label for="ctrl_custom_field_ndq5ody">Проверка:</label></dt>
    <dd>
        <input type="text" name="03df4761f3b5dfa25897bee716e04c02[ndq5ody]"
               id="ctrl_custom_field_ndq5ody" class="textCtrl" />
        <p class="explain">Пожалуйста, оставьте это поле пустым.</p>
    </dd>
</dl>
```

**Важно:** подпись «Пожалуйста, оставьте это поле пустым» означает что
это honeypot-поле антиспам защиты — его нужно оставить пустым, а не
заполнять вручную.
