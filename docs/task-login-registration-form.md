# 🎯 Задача: Поддержка форумов с объединённой формой логина/регистрации

## Описание задачи

Форумы типа XenForo (и другие движки) используют одну форму для логина и регистрации
на странице `/login/`. Текущая логика жёстко исключает формы с `action="login"` →
форма не обрабатывается → форум помечается как неудача.

**Пример проблемного форума:** `https://forum-msk.info/login/`

```html
<form action="login/login" method="post" class="xenForm" id="pageLogin">
    <input type="radio" name="register" value="1" /> Нет, зарегистрироваться сейчас.
    <input type="radio" name="register" value="0" checked /> Да, мой пароль:
    <input type="submit" value="Вход" data-loginPhrase="Вход" data-signupPhrase="Регистрация" />
</form>
```

При выборе radio «Нет, зарегистрироваться» — кнопка меняет текст на «Регистрация»,
страница не перезагружается, форма отправляется с `register=1` → сервер регистрирует аккаунт.

---

## 🎯 Решение (два компонента)

### Компонент 1 — Мягкое исключение форм логина

**Текущее поведение:** формы с `action="login"/"signin"` жёстко исключаются из кандидатов.

**Новое поведение:** вместо исключения — штраф `-20` к score, аналогично существующим:
```python
# Уже есть в коде:
username_без_email(-20)
email_без_username(-20)
# Добавить:
action_содержит_login(-20)
```

Это позволит:
- Форумам с отдельной формой регистрации — игнорировать форму логина (она будет последней)
- Форумам с объединённой формой — обрабатывать её если других блоков нет

### Компонент 2 — Обработка radio-кнопок

**Текущее поведение:** `input[type='radio']` игнорируется или попадает в `custom_fields` без обработки.

**Новое поведение:**
- `identify_fields` определяет radio-кнопки с ключевыми словами регистрации
- Перед заполнением полей скрипт кликает нужную radio-кнопку
- Логика выбора значения: шаблон → `common_fields.json` → эвристика по ключевым словам

## 🔍 Контекст для анализа

### Текущая логика исключения форм логина (`selector_finder.py`)

Фильтрация происходит в двух местах метода `find_registration_form`:
1. По атрибутам формы (`action`, `name`, `id`) — жёсткое исключение через `continue`
2. По содержимому блока `combined_block` — жёсткое исключение через `continue`

Нужно найти оба места и заменить `continue` на `score -= 20`.

### Текущая логика identify_fields (`selector_finder.py`)

Radio-кнопки попадают в ветку `type=checkbox` — нет, они имеют `type=radio` и
**не обрабатываются** специально. Нужно добавить ветку для `type=radio`.

### Ключевые слова для radio регистрации

Добавить в `common_fields.json` новый ключ:
```json
"register_radio_keywords": [
    "register", "sign up", "зарегистрироваться", "регистрация",
    "нет, зарегистрироваться", "create account", "новый пользователь"
]
```

### Логика обработки radio в `_fill_fields`

Новый шаг **перед шагом 1** (заполнение полей):
```
ШАГ 0: radio-кнопки регистрации
├── найдены radio с register_radio_keywords → кликаем нужную
├── значение из шаблона → приоритет
├── эвристика по ключевым словам из common_fields
├── ручная обработка в случае не зрабытыванмя данных из шаблона, common_fields или эвристики
└── клик → пауза для JS-обновления формы
```
